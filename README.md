# x-小说拓展

一个把小说网页变成「自己的阅读器」的浏览器扩展：**识别到小说章节页就自动切换**，进入后只有正文，没有广告、没有推荐、没有下载浮层；遇到被拆成 `（1/3）(2/3)…` 的章节，会**自动抓取后续页并拼成一篇完整正文**。

> GitHub 仓库：<https://github.com/Niger12138/x-novel-extension>  
> 安装包：仓库 `dist/x-小说拓展-1.1.7.zip`，或 [Releases](https://github.com/Niger12138/x-novel-extension/releases) 下载。

- 版本：1.1.7
- 适用：Microsoft Edge / Chrome（Manifest V3，桌面端）
- 权限：`storage`、`tabs`（不加载远程代码，不上传页面内容）
- 1.1.1 修复：右下角「进入纯净阅读」因 `pointer-events` 继承而点击穿透；现在鼠标、键盘都能进入，提取失败时入口保留，不会点一下就没。
- 1.1.2 修复：点「下一章」后新章错误恢复上一章的滚动位置（尤其 `?chapter=3` / `?chapter=5` 这类同路径章节）导致一进入就在底部；现在进度按「URL 查询参数 + 章节标题」分别记录，新章从开头读。
- 1.1.3 优化：普通网页只在「正文已定位 + 章节语境 + 分数≥38」时才净化，避免误伤新闻/购物站的横幅；退出阅读后短暂出现「继续纯净阅读」胶囊；分页没拼完整时明确标记并阻止误跳章；关闭悬浮入口后当前站点会话不再重复弹；弹窗新增「最近阅读」入口。
- 1.1.4 修复：目录不再只扫描当前章节页的「上一章 / 下一章」，而是抓取「目录」入口指向的原站目录页，补全整本书章节；自动进入增加「强章节语境兜底」，短章节页只要同时有上一章、下一章和章节标题，也能自动进入。
- 1.1.5 修复：笔趣阁一类站点用 `<div id="content">` 装整章、段落只靠 `<br>` 分隔，旧的 blockCount 只算 1，导致 98 分也不自动进入；现在按实际 `<br>` 分行计算段落。已用 `bqge.com/shu/0u4h/139/` 实测：自动进入、拼接 3 页、2114 字。目录入口写成「书名 + 章节目录」时也能识别；目录会跳过「最新九章」，并逐页抓取分页目录（bqge 实测 553 章，不再只显示第一页 109 条）。
- 1.1.6 修复：拼接完成后点「下一章」有时会拿到本章分页地址（例如 `/139/2/`），结果回到本章第二节。现在合并阶段会过滤“当前章分页”候选，优先使用最后一页真正的「下一章」；真实 bqge 页已验证从 `139` 进入 `140`，不再回到 `139/2`。
- 1.1.7 修复：分页请求失败、只拼到一半时，初始的 `/2/` 仍可能留在「下一章」上。现在点击时会先识别“本章分页”并拦住，再从原站目录定位真正的下一章。真实 bqge 143 实测：强制阻断本章 2/3 页请求后，点两次「下一章」仍能到 144，不会回到 143/2。

## 一、安装

1. 解压 `x-小说拓展-1.1.7.zip`，得到 `x-小说拓展` 文件夹。
2. 打开 `edge://extensions`（Chrome 为 `chrome://extensions`）。
3. 打开左下角「开发人员模式」。
4. 点「加载解压缩的扩展」，选择 `x-小说拓展` 文件夹。
5. 回到已经打开的小说页，**刷新一次**，扩展开始工作。

> 首次安装或升级后必须刷新页面，内容脚本才会重新注入。升级扩展时，建议把已经打开的小说标签页全部关闭再重新打开——只刷新扩展管理页，旧标签页里仍然跑旧脚本，弹窗却可能已经显示新版本。

## 二、怎么用

| 场景 | 操作 |
| --- | --- |
| 打开小说章节页 | 识别达标后约 0.45 秒自动进入纯净阅读 |
| 章节被拆成 1/3、2/3 | 进入后自动抓取本章后续页，顶部显示「已拼接 N 页」 |
| 想临时关掉 / 打开 | `Alt+R` |
| 退出后想回来 | 右下角短暂出现「继续纯净阅读」，点它即可；6 秒后自动收起 |
| 看识别分数和依据 | 点工具栏的扩展图标 |
| 找上次读到哪 | 弹窗顶部「最近阅读」展开，点条目回到原章节 |
| 换主题、调字号、开关自动进入 / 拼接分页 | 弹窗，或在阅读器里按 `Aa` |
| 切上一章 / 下一章 | 底栏按钮，或键盘 `←` `→` |
| 翻页 | 鼠标滚轮、`↑` `↓`、`PageUp` `PageDown` |
| 退出 | 右上角 × 或 `Esc` |

阅读器内提供：6 套主题（纸白 / 米黄 / 护眼绿 / 雾蓝 / 夜间 / 纯黑）、字号 14–40、行距、版心宽度、宋/黑/楷三种正文字体、首行缩进、章节目录、阅读进度记忆、自动连读（读到底部 6 秒倒计时进入下一章）、分页章节拼接。

不进入阅读器时，原页面也会被就地净化：广告位、推荐模块、App 下载条、悬浮窗会被隐藏，正文保持原样。

## 三、识别机制

### 3.1 这类「阅读模式」的共性

浏览器的阅读模式（含夸克一类产品）公开可观察到的做法，核心是三件事：

1. **正文定位**：在页面里找出承载正文的那个节点；
2. **噪声剔除**：把广告、推荐、导航、评论区从正文里剔除；
3. **自动触发**：确认「这一页大概率是一篇小说章节」后，不再要求用户手动点按钮。

它对**能解析出正文的文字页**有效；漫画章、纯图片章、正文要登录或付费才出现的页面，通常拿不到内容。

本扩展按同样思路自研，不依赖任何站点私有接口；1.1.2 额外补上了「章内分页」这一层。

### 3.2 三层正文定位

```
站点规则（起点/番茄/晋江/纵横/17K/刺猬猫/SF/轻之文库/七猫/biquge 系）
        ↓ 没命中
通用选择器（#content / .content / .read-content / article …）
        ↓ 都不过校验
正文密度聚类（一次遍历统计文本量、链接占比、段落数，取最优节点）
        ↓
refine：向上找更完整的容器，剔除首尾的导航/广告小块
```

通用选择器不是「有就认」：必须同时满足字数、段落数、链接密度校验，否则继续往下走。分页章节的单页正文往往只有 400–500 字，所以 1.1.2 把站点规则的字数门槛降到 320、通用选择器降到 380，避免「正文明明在，却因为太短被丢掉」。

### 3.3 打分信号

识别不是单看字数，而是多信号加权（`content/detect.js`）：

| 信号 | 分值 |
| --- | --- |
| 命中站点规则 | +46 |
| 域名像小说站 | +16 |
| URL 含 chapter / book / 数字章号 | +12 |
| 页面有上一章 + 下一章 | +14 |
| 只有单个章节翻页链接 | +7 |
| 只有章内「上一页 / 下一页」 | +8 |
| 页面有目录入口 | +5 |
| 标题含「章 / 回 / 节 / 无弹窗 / 全文阅读」 | +8 |
| 正文里有章节标题结构 | +8 |
| meta 关键词含小说 | +4 |
| 识别为章内分页页 | +8 |
| 正文长度 ≥1500 / ≥800 / ≥400 字 | +12 / +9 / +5 |
| 段落数 ≥8 / ≥4 | +6 / +4 |
| 链接密度 ≤0.08 / ≤0.2 | +6 / +4 |
| 中文占比 ≥0.6 / ≥0.4 | +5 / +3 |
| 有对白 | +3 |

惩罚项：链接密度 >0.35 −22、正文 <400 字 −22、段落 <3 −10、一个小说特征都没有 −12。

**自动进入条件（1.1.4 起）**：正常仍要求分数 ≥55，且正文 ≥400 字、段落 ≥3、具备章节语境。另外增加「强章节语境兜底」：分数 ≥38、正文达到 300–320 字、段落 ≥3、确实有章节语境，并且满足以下任意一条时也自动进入——已知小说站 / 小说域名；同时出现「上一章 + 下一章」；章内分页明确可跟随。普通长文没有这些信号，仍然不会被自动拉进阅读器。

**段落计数（1.1.5 起）**：像 `bqge.com` 这种整章塞在一个 `<div id="content">` 里、段落之间只用 `<br>` 的页面，不再按「1 个 block」处理；检测阶段会把实际 `<br>` 分行计入段落数。否则会出现分数 98、正文 700+ 字，却因为「段落 <3」被拦在自动进入之外的情况。

**净化门槛（1.1.3 起）**：原页面净化不再「有广告类名就隐藏」。只有正文节点已定位、存在章节语境、且分数 ≥38 时才启动；普通新闻、购物、工具站即使有 `banner / promo / download` 类名，也不会被误伤。

**为什么还要兜底**：很多真实章节页正文只有 300–400 字，标题还可能只写「林蛙（1/3）」，分数落在 38–54；旧版能显示悬浮入口，但不会自动进入。1.1.4 不再单看 55 分，而是看「是不是一章」：有明确的上下章、章节标题、章内分页或已知小说站，就可以进。1.1.5 又补上了 `<br>` 段落计数，覆盖笔趣阁类站点。

**为什么从 62 降到 55**：未知小说站常常只有一个「上一章 / 下一章」加章节标题，得分正好在 55–61 之间；旧版差 1–2 分进不去，用户会觉得「自动进入不管用」。升级时如果检测到旧配置里仍是默认的 62，会自动迁移到 55；用户自己改过的值不动。

**悬浮入口**：分数 ≥38，或命中强章节语境兜底时，页面右下出现「进入纯净阅读」，不打扰阅读。入口本身单独开启 `pointer-events:auto`，宿主容器仍是事件穿透，不会挡住网页；鼠标点击和键盘 Enter 都能进入阅读器，× 只收起入口。

### 3.4 章内分页：识别与拼接

有些站点会把一章切成多个物理页面，标题写成「林蛙（1/3）」「第 2 页 / 共 3 页」，正文末尾再来一句「本章未完，点击下一页继续阅读」。

1.1.2 的处理流程：

```
解析标题 / h1 里的 (1/3)、第2页/共3页
        ↓
把导航拆成两组：
  章节级：上一章 / 下一章 / 目录
  章内级：上一页 / 下一页
        ↓
确认是分页章节（有分页标记，或“本章未完”+ 章节标题）
        ↓
按章内“下一页”逐页 fetch（同源、9 秒超时、最多 10 页）
        ↓
DOMParser 解析 → 复用同一套正文提取 → 校验标题同章
        ↓
段落去重、过滤“本章未完 / 1/3”提示行、按顺序拼接
        ↓
“下一章”改用最后一页的章节级链接，避免又跳回第 2 页
```

关键点：

- **导航必须分开**。旧版把「下一页」和「下一章」都塞进一个 `next`，分页页点“下一章”实际跳到第 2 页；现在 `chapterNext` 与 `partNext` 分开，阅读器的“下一章”永远优先取章节级链接。
- **不跨章合并**。每一页抓回来都要和第一页标题比对（忽略 `(2/3)` 标记后比较前 14 个字），标题不同就停止，避免把下一章误拼进来。
- **失败可降级，但不再假装完整**。某一页 404、超时、需要登录或跨域，会保留已拼好的部分；结尾改为「本章分页未完整拼接」，下一章按钮变成「仍要进入下一章」，首次点击只提示二次确认，不会直接跳走；自动连读也会被禁用，避免悄悄漏掉缺失页。
- **抓取只用同源请求**。`fetch(url, { credentials: 'same-origin' })`，不带第三方域名、不上传内容；需要登录的站点会带上当前浏览器的同源 Cookie。

### 3.5 目录怎么来的（1.1.4 / 1.1.5）

旧版目录只扫描**当前章节页**上的 `a[href]`，还要求链接文字含「第X章」。现实中的章节页通常只有「上一章 / 目录 / 下一章」，所以目录经常是空的；某些页面又会把侧栏推荐里的零散章节链接抓进来，看起来「根本不对」。

1.1.4 改成两层：

1. 打开目录面板时，先把当前页能确认的章节链接显示出来，避免空白等待；
2. 如果页面有「目录」入口（`data.toc`），在后台用同源 `fetch` 抓取该目录页，`DOMParser` 解析后补全目录。

1.1.5 又修了三处真实目录问题：

- **入口文字**：bqge 的链接写的是「年代1982：每天一条赚钱情报章节目录」，旧规则只认开头是「目录」的链接，所以 `data.toc` 一直为空；现在同时认结尾的「章节目录」。
- **最新九章混入**：bqge 目录页先列「最新九章」再列正式目录，直接扫全页会把第490章排在最前面；现在优先取标题含「章节目录 / 全部章节」的分组，跳过「最新 / 推荐 / 书友」分组。
- **只读第一页**：bqge 目录分 6 页，每页 100 章，旧版只抓第一页，109 条里还混着 9 条最新章；现在读取 `.toc-pager` 的分页并逐页补全，去重后完整 553 章（实测）。

目录面板会标明来源：`原站目录 · N 章` 或 `当前页可用章节 · N 条`；读取成功会 toast「已读取原站目录」，失败则保留当前页结果，不会把已有目录清空。当前页的临时结果还会按「上一章 / 下一章 / 目录」所在的书路径过滤，避免把侧栏里别的书的推荐章节混进来。当前章节会在列表里高亮，并自动滚到面板中间，几百章的书也不用自己翻找。若目录页本身是登录后 / JS 动态渲染，抓不到时仍保留「打开原站完整目录」按钮，可直接去原站看。

### 3.6 自动进入为什么更稳了

旧版只在页面加载后 15 秒内复检 6 次，遇到正文延迟加载或 SPA 换章就放弃。1.1.2 改成三层兜底：

- `MutationObserver` 跟随 DOM 变化 30 秒，最多 18 次增量识别；
- 1.5 秒轮询一个「页面签名」：`URL + 标题 + h1 + 正文长度分桶`；签名变了就重新识别，专门处理 SPA 换章（URL 不变但标题/正文变了）；
- 没有明显变化时，前 2 分半钟每 6 秒再识别一次，抓住「正文很晚才出现」的站点。

退出标记也从 `xn_exit:<url>` 改成 `xn_exit:<url>|<title>`：同一个地址换章后标题变了，允许重新自动进入；同一章刷新仍然尊重「我刚退出过」。

### 3.7 进入之后

- **Shadow DOM 隔离**：阅读器挂在自己的 Shadow Root 里，站点 CSS 改不动它；它也不会污染站点。
- **只渲染提取后的块**：正文按段落重建，广告和推荐根本没有机会进入阅读视图。
- **原页面同步净化**：类名/属性（`ad`、`banner`、`recommend`、`data-ad`…）、推荐模块标题（猜你喜欢、本周热榜、相关推荐…）、整屏下载浮层、被清空的侧栏，都会被隐藏。正文节点及其祖先受保护，不会被误伤。
- **状态保持**：退出后写 `sessionStorage` 标记，避免刚退出又被自动拉回去；每站可单独关闭「本站自动进入」；阅读位置按「域名 + 路径 + 查询参数 / hash + 章节标题」分别记忆，最多 80 条。这样 `?chapter=3` 滚到底后点下一章到 `?chapter=5`，新章会从开头读；同一章刷新仍回到上次位置。1.1.3 起，退出阅读器后右下角会短暂出现「继续纯净阅读」胶囊，6 秒后自动收起；点过悬浮入口的 × 后，当前站点本次标签页会话内不再重复弹出普通入口。
- **最近阅读**：弹窗会从已保存的阅读位置里取最近 5 条，显示章节标题、站点、进度和最近时间；展开后点击条目直接打开原章节，回到上次位置。
- **拼接状态可见**：进入后先显示第一页，顶部元信息显示「正在拼接…」，后面几页在后台抓取；完成后变成「已拼接 N 页」，并 toast 提示总页数与字数。

## 六、隐私与权限

- 扩展本身不加载远程代码、不上传页面内容、不接入任何第三方统计。
- **唯一会主动发起的请求**是分页拼接与目录补全：分页拼接只请求当前站点、当前章节的后续页；目录补全会请求当前站点「目录」入口指向的目录页，用于列出章节。两者都只用同源 `fetch`，不跨站、不请求广告或推荐接口、不上传页面内容。
- `storage`：保存设置、每站开关、阅读位置。
- `tabs`：弹窗读取当前标签页并向内容脚本发消息（查状态、进入 / 退出）。
- 内容脚本只注入 `http/https` 页面，不碰浏览器内置页、扩展页。

## 七、已知边界

- **只处理文字正文**：漫画章、图片章、扫描版、正文需登录/付费才出现的页面可能识别不到。
- **分页拼接依赖页面给出可跟随的「下一页」链接**。如果站点用 JS 动态加载、按钮没有 `href`，或者后续页跨域、需要验证码，扩展只能保留当前页并提示失败。
- **最多拼 10 页**，避免异常站点把整本书拖进内存；标题里没有页数、也没有「本章未完」提示的软分页，会按实际可抓到的链接继续，直到没有下一页或标题不再同章。
- **目录抽屉**依赖页面本身有「第 X 章」这类目录链接；只有上一章/下一章时，目录会是空的。
- **站点改版**会让个别选择器失效，此时回退到通用选择器与密度聚类，多数仍能识别，但排版细节可能不如专用规则。
- **净化按视觉特征判断**：极少数把广告伪装成正文段落、或把推荐写成纯文本的站点，可能漏过。
- 与其它阅读类扩展同时启用时，可能互相覆盖页面样式，建议只留一个。
